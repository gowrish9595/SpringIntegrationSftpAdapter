# Tech Refresh & Software Request Policy

This document captures the End User Computing (EUC) tech refresh procedure and
the associated non-standard software request controls, in line with MAS asset
management audit requirements and the MIS Risk Register.

## 1. Tech Refresh — 1-for-1 Swap

Tech refresh is a strict **1-for-1 swap**. A user will not hold two laptops at
the same time.

- Contact EUC only when you are ready to swap.
- EUC can safekeep the old laptop for **up to 1 week** before deletion if
  required.
- If software needs to be installed on the replacement laptop, the request
  form must be filled and **endorsed by the HOD beforehand**.

### User responsibilities before the appointment

1. Housekeep and back up any data required for the new laptop to personal
   OneDrive or the Q Drive. Files are primarily under
   `Desktop/`, `Documents/`, and `Downloads/`.
2. EUC is **not liable** for any data loss during issuance of new equipment.
3. Any non-standard software (outside the Corporate software list) requires a
   Risk Assessment and IS team approval **before** the refresh proceeds.
4. Prepare the following for return:
   - Laptop
   - Laptop charger
   - Docking station
   - USB mouse
   - Laptop bag
5. Once the above is ready, reply to the EUC email to book the tech refresh
   appointment.

## 2. Corporate Standard Software

- Corporate standard software is preinstalled on all corporate machines by
  default.
- Optional software is available on request; the requestor is responsible for
  any license procurement where applicable.
- For software that is not on the approved list, the requestor is responsible
  for:
  - License procurement (where applicable)
  - Software approval submission
  - Furnishing EUC Helpdesk with periodic security vulnerability patches or
    the latest software version in a timely manner, in line with Information
    Security's patch management policy.

## 3. Non-Standard Software — Security Assessment

As per the MAS audit on asset management (including software) and the MIS Risk
Register, software installation requests for corporate endpoints are tightened
to include a security assessment for non-standard software. The assessment
covers Asset, Patch, and Obsolescence Management.

### 3.1 Asset Management

For all non-standard software (licensed or freeware, user-developed
applications, and in-house managed app clients), the requester — or the IT
custodian where applicable — is responsible for ensuring:

- The installer is from a legitimate / verifiable source.
- Legal terms on free-for-use applications are not breached (many freeware
  packages are not free for commercial use).
- License count and/or maintenance support is valid for paid applications
  during the request period, and is promptly removed once the licenses or
  maintenance are no longer valid.

### 3.2 Patch Management

The requester — or the IT custodian where applicable — is responsible for
ensuring:

- The installer is free from malware, adware, and spyware.
- Security vulnerabilities (including zero-day) of applications are
  monitored, tracked, and where applicable, the required patch is provided
  to Helpdesk for deployment in accordance with the IS patch management
  timeline.
- Indicators of Compromise (IOCs) from regulators are monitored, tracked,
  and where applicable, the required patch is provided to Helpdesk for
  deployment in accordance with the IS patch management timeline.

### 3.3 Obsolescence Management

The requester — or the IT custodian where applicable — is responsible for
ensuring:

- End-of-Service-Life (EOSL) is monitored and tracked.
- A tech refresh plan is initiated, or the required updated version is
  provided to Helpdesk for deployment, whichever applies.

## 4. Deviations & Dispensations

Where **one or more** of the conditions in Section 3 are not met, the
requester — or the IT custodian where applicable — must demonstrate that an
**IT deviation / dispensation** is in place prior to the software
installation request.

Helpdesk will only allow the software to remain installed during the IT
deviation period, and will remove it promptly thereafter.
